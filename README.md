# What Language Labels Leave Out: An Absorbing Class in Corpus Language Identification

Reproduction package for the paper by Romin Oli.

arXiv: to be added on posting.

The repository holds identifiers, predictions, results, code and protocols. It holds no third-party text. Every evaluated text is rebuilt from the named external corpora and checked against a stored hash.

## Contents

- `paper/`: the paper (`instrument paper.pdf`) and its LaTeX source. `tables/` and `figures/` are generated by the scripts below.
- `data/`: the units and what the identifiers did with them.
  - Unit files (`*_units.csv`, `reader_sample.csv`, `angika_extract_*.csv`) give each unit's corpus, language, length, source identifier and the SHA-256 of its NFC-normalised text.
  - Prediction files (`*_predictions_*.csv`) give each identifier's top-1 label and, where recorded, its score.
  - `panel_source_clusters.csv.gz` gives the source clusters used for resampling.
  - The marker lists are `angika_markers.json`, `maithili_markers.json` and `newari_markers.json`.
  - `model_identities.json` and `model_labels.json` identify the identifiers and their label sets.
  - `external_inputs.json` lists the external corpora.
  - `fineweb2_listing.json` and `fineweb2_row_counts.json` hold FineWeb-2 file metadata.
- `analysis/`: the scripts. Each begins with a short description of what it reads and writes.
- `results/`: machine-readable results, one file per analysis. `provenance.json` records, for each group of reported results, its kind, source, script and governing protocol, and which results survive only as recorded aggregates.
- `protocols/`: the rules each analysis followed. Each protocol states its status (pre-specified, hypothesis-informed or post hoc), the date its rules were fixed, its conditions and its outcome. The protocols are:
  - 01: Panel 1 and the three-release comparison;
  - 02: the cross-identifier comparison;
  - 03: confidence scores;
  - 04: the reader-judged sample;
  - 05: Panel 2 and the L20 cells;
  - 06: Angika markers, tagger and segmenter;
  - 07: the Angika-labelled released split;
  - 08: source-cluster resampling;
  - 09: the length characterisation and the Awadhi split;
  - 10: the published training files;
  - 11: prior exposure;
  - 12: reader-sample reuse, nested units, source concentration and OpenLID-v3;
  - 13: the Maithili and Newari marked subsets;
  - 14: the seven-source composition;
  - 15: register;
  - 16: n-gram proximity;
  - 17: label inventories.

## Requirements

Python 3.11 and the packages in `requirements.txt`:

    pip install -r requirements.txt

fastText, py3langid and gcld3 are needed only to rerun the identifiers. gcld3 builds from source and needs the protobuf compiler (`protoc`) and a recent setuptools; installing it inside a virtual environment avoids conflicts with system packages.

## 1. Rebuild the texts

Obtain the external inputs listed below and put them in one folder. Then run:

    python analysis/rebuild_texts.py --inputs /path/to/inputs

The folder is searched recursively. A file is found by its listed name or, failing that, by its size and SHA-256.

The script writes `texts/`, which is not tracked, and confirms every rebuilt text against its stored hash. It exits with status 1 if any text differs. The Wikipedia, FLEURS and IndicVoices pulls are harvests. A new harvest can differ from the one used, and the hashes show whether it does.

## 2. Recompute the results

Most analyses read only `data/`:

    cd analysis
    python panels.py
    python released_splits.py
    python nested_reader.py

The same holds for `openlid_v3.py`, `composition.py`, `label_diff.py`, `reader_crosscheck.py`, `reader_agreement.py`, `runner_up.py`, `angika_groups.py` and `ngram_decompose.py`.

Some analyses also read `texts/` or an external file directly: `source_clusters.py`, `marked_subsets.py`, `nested_construction.py`, `overlap.py`, `register.py`, `decompose.py`, `ngram.py`, `ngram_length.py` and `training_file.py`. Set `INSTRUMENT_INPUTS` to the inputs folder before running them. Run `source_clusters.py` before `panels.py`.

## 3. Regenerate the tables and figures

    cd analysis
    python make_tables.py
    python make_figures.py

These write `paper/tables/` and `paper/figures/`. The paper builds with `xelatex`, `bibtex`, `xelatex`, `xelatex`.

## 4. Check the numbers

    python analysis/check_results.py            # analyses that read only data/
    python analysis/check_results.py --texts    # all analyses; needs texts/ and INSTRUMENT_INPUTS

The check does three things:

1. It reruns every analysis into a scratch copy and compares each value with `results/`.
2. It regenerates every table and compares it cell by cell with `paper/tables/`.
3. It recomputes each figure reported in the text, rounds it half-up to the printed precision, and confirms that the printed value appears in the paper's source.

It exits with status 1 on any failure.

## 5. Rerun the identifiers (optional)

    python analysis/predict.py fasttext v3 panel1 --artefact /path/to/model_v3.bin
    python analysis/predict.py langid langid panel1
    python analysis/score_openlid_v3.py /path/to/openlid-v3.bin
    python analysis/training_file.py --v1 /path/to/model_v1.bin --v2 /path/to/model_v2.bin

Each fastText binary is refused unless its SHA-256 matches the value below. `predict.py` writes to `fresh/` and reports how many units carry the recorded label.
